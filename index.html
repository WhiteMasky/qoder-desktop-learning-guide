00 · 先看这页，避免学错产品

这本手册讲什么，哪些没有冒充“验证过”

这里的 Qoder 是独立应用 Qoder Desktop。Qoder IDE、CLI、JetBrains 插件和 Agent SDK 是不同产品，不能把它们的快捷键、设置文件或版本说明直接套用。

本公开版依据 Qoder Desktop 官方资料与功能说明整理，保留必要的英文按钮名，便于对照界面。它不包含个人设备配置、账号状态或会话执行记录；不代表读者已经安装、开启或验证了相应能力。功能入口、中文译名和布局可能随平台及版本变化。

覆盖承诺：这是一份覆盖主要模块、按钮、设置和工作流的详细学习手册，不是“所有平台、所有企业策略、所有第三方插件动态界面都逐像素测试通过”的证明。未见到的隐藏入口、账号资格、实时价格、私有服务权限仍是未知。
证据标记准确含义不能推出什么
已保存 / 已回读设置接口返回了持久化值。不保证系统权限、其他设备或所有场景立即生效。
已就绪 / 已连接连接器状态正常，或当前会话具备工具接口。不表示已认证每个账号，也不表示每个业务操作都测试成功。

待你操作 / 按需需要登录、授权、选择目标或提供材料；或不适合默认开启。不是悄悄开通了，也不是产品没有这项功能。

01 · 通用 Agent 配置检查方法

“适合通用”不等于“全部开关打开”。优先配置可观察、可控制、能产出文件的能力；外部账号和高影响动作按任务授权。本章是自查方法，不是任何个人设备的配置记录。

1.1 先检查基础能力，不重复安装
能力怎么检查验收边界
文件与工作目录选择专门的练习目录，让 Agent 生成一个不含隐私的测试文件，再自行打开。先确认保存位置与内容；不要用重要资料练习覆盖或删除。
Office检查 Word、Excel、PPT 相关能力是否已安装、启用并能在当前会话使用。连接就绪不等于所有格式可靠；用虚构数据测试可编辑文件。
PDF先确认任务是提取、拆分、合并、转换还是 OCR，再选择能力。Poppler 等文本工具不等于通用 OCR，扫描件要单独验证。
过程可观察性查看工具调用计数、任务监控、产物与错误信息。显示开关不改变执行权限；工具“完成”不保证业务目标达成。

安装额外扩展前先检查已有能力、来源、版本、权限与依赖。遵循当前操作系统的官方安装方法，不把其他平台命令直接照搬。

1.2 选择有边界的默认设置
设置学习期建议为什么
通知按需开启权限请求与等待回答提醒；轮次完成通知可选择仅未聚焦时。App 设置和操作系统许可需要分别核对，实际送达还应观察。
运行中发送理解“排队”和“插话”的区别，再选择默认方式。默认排队适合避免打断；紧急纠正可使用支持的插话入口。
目标轮数先采用有限轮数，明确验收标准和停止条件。轮数不等于时间或费用；“不限”不是好结果的前提。
记忆先理解全局与项目作用域，只保存稳定、适合复用的信息。关闭不等于删除；不要把敏感凭据当成记忆内容。
权限与建议保留必要审批；审阅提示建议和 Skill 自进化建议。建议不等于执行授权，也不等于已经修改配置。
1.3 连接浏览器与系统能力时怎样配合
事项正常入口检查标准
外部 Chrome / Edge设置 → 电脑操控 → 浏览器；按当前界面指引安装或打开 Qoder Browser Connector 并连接。Agent 能发现指定浏览器，并在新建的无需登录的公开页面完成只读检查。安装、连接、网站登录是不同状态。
系统通知设置 → 常规 → 通知 → 系统通知设置，或使用系统自身的通知设置。确认 Qoder 被允许发送通知，再观察正常任务提醒；不是只看 App 内的开关。
桌面控制使用当前平台支持的电脑操控入口与官方环境指引。先截图确认目标桌面，再做无副作用操作；鼠标键盘接管时明确交接。
网站账号 / OAuth在服务自己的页面私密完成登录与授权。检查目标账号和最小必要范围，不把密码、验证码或 Token 发进聊天。
一般文件处理和办公任务不依赖外部浏览器。没有具体需求时，不必为了“全功能”绑定所有账号、设备和云服务。
1.4 哪些能力不应默认全部开启

完全访问、无限目标轮数、多层委派、高副作用 Hooks、无人值守自动化、远程设备全范围访问、代码上传扫描或索引、云资源、BYOK、麦克风、录音与声纹，都应结合具体任务、费用和隐私边界决定。

不必一开始就创建大量自定义 Agent 或持久团队。先用默认入口完成几类真实但低风险的工作，再把稳定的方法沉淀为 Skill，把明确的职责做成 Agent。

自查结论应分层：已安装、已启用、已连接、已认证、当前可调用和业务验收成功分别记录；不能用“全部开启”替代真实检查。

02 · 七次学习路线：每次只练一个重点

建议每次 20–40 分钟。这是学习安排，不是产品执行时长保证。勾选表示你自己确认掌握，并不自动调用 Qoder 或执行练习。

0 / 7 课完成

第 1 课：把一句需求变成一个可检查的文件

先读：第 03–05 章。掌握新任务、工作目录、输入框、文件链接。练习：新建一个练习目录，要求 Qoder 用你提供的三条虚构事项做一份今日计划，保存成 HTML 或 TXT，不联网、不改已有文件。

验收：你能说出文件存在哪里；打开文件确认三条事项都在；能区分“聊天里描述了文件”和“文件实际存在”。复述：目标、材料、输出格式、约束、验收标准各是什么？

第 2 课：学会给上下文，而不是要求它猜

先读：第 05、08、15 章。练习 @ 文件、附件、/ Skill 和当前任务查找。给两份虚构资料，让 Qoder 比较不同之处，每条结论注明出处；资料没有的内容必须写“未提供”。

验收：随机抽三条结论能找到对应原文。你能解释文件引用、上下文摘要和长期记忆的区别。

第 3 课：用计划、目标和监控管住执行

先读：第 06–07 章。先在计划模式中要求“把练习目录的文件按主题分类，先列计划，不修改”。审阅确认后只操作副本；另做一个最多几轮、目标明确的小任务，观察任务监控。

验收：能找到计划、目标、工具结果、产物；知道排队、插话、停止、暂停目标、撤销文件修改分别做什么。不要用真实重要目录练习删除。

第 4 课：完成一条办公交付链

先读：第 11 章。使用虚构支出表，生成可编辑 Excel 汇总，再按结果写一页 Word 说明或三页 PPT。最后用测试 PDF 做拆页/合并练习。

验收：Excel 手算核对一组总和；Word 无截断；PPT 可编辑；PDF 合并前后页数一致。扫描 PDF 没文字时，不把空提取误认为成功。

第 5 课：浏览器、电脑控制与权限边界

先读：第 09、18、21 章。先检查当前执行设备，再让 Agent 读取一个无需登录的公开网页并总结。连接完成后，可以练习外部浏览器与内置浏览器的区别，不必为练习登录新账号。

验收：你能分清内置浏览器、外部 Chrome/Edge 和桌面控制；知道看到登录框时该由自己接管；知道停止不能收回已经发出的外部请求。

第 6 课：把重复工作沉淀成能力

先读：第 13–17 章。先判断重复的是“方法”（Skill）、“接口”（MCP）、“角色”（Agent）、“时间触发”（自动化）还是“资料”（知识库）。写一份角色草稿，先不要创建团队或开定时任务。

验收：能说明为什么选择该类型；明确输入、输出、工具范围、错误处理与停止条件。若创建自定义 Agent，必须亲自审阅配置并保存。

第 7 课：独立完成一个小项目并复盘

先读：第 12、22–24 章。任选“公开资料研究报告”“本地交互说明页”“已有小程序修复”。写目标、非目标、交付格式和验收标准；用少量必要工具完成，不为了展示而堆插件。

验收：交付文件可打开；关键结论有来源；知道哪些未验证；没有未授权发布；完成本手册自测，错题能说明理由。若要分享，先检查私密资料再授权。

03 · 用一张心智地图理解产品

3.1 Qoder 不是只会聊天：它围绕任务组织执行
目标与材料→计划与权限→工具执行→文件或外部结果→验证与迭代

聊天回复只是过程和结果的一部分。真正的产物可能是 DOCX、Excel、PPT、脚本、网页、代码修改，也可能是经你授权的外部服务操作。不同结果需要不同验证：文章查证据，表格查计算，网页查交互，代码跑测试。

本地 Agent 不等于完全离线。工具可以在本机操作文件，但模型推理、联网研究、知识服务、代码索引或云端执行仍可能发送数据。决定敏感材料能否使用，要看具体模型、服务、策略和执行位置，不只看“本地”两个字。

3.2 十个常见名词：别把它们当成同一种东西
名词通俗解释典型例子
任务 / 会话围绕一个目标积累的消息、上下文和执行记录。把这批资料做成培训课件。
工作区 / 文件夹文件与工具的工作范围、执行位置的一部分。本机某项目目录；不等于云协作 Project。
模型理解需求、推理、生成内容的能力来源。按复杂度、速度和成本选择。
Skill某类任务的方法、规范、参考材料和可选脚本。制作 PPT、处理 PDF。
Connector / MCPAgent 调用外部服务或本地工具的接口。GitHub、Office 工具。
Plugin装在一起的一组能力，可包含 Skill、MCP、Agent、命令、Hook。具备工具与操作界面的整套扩展。
Agent拥有固定角色指令、模型、权限与能力范围的执行者。只做材料审核的助理。
Agent Team有负责人和成员的可复用协作配置。负责人分派研究、撰写、校验。
Memory / 知识记忆存稳定偏好；知识库存参考资料；Repo Wiki 解释代码库。回答语言偏好 / 制度文件 / 项目架构。
Automation / Hook前者按时间运行任务；后者对生命周期事件作出处理。每天汇总 / 工具执行前检查。

04 · 工作台、新任务与入口导航

4.1 从左到右看界面：一块管组织，一块管对话，一块管产物
区域 / 按钮作用与基本用法容易误解的地方
编程 / 通用左上模式切换。编程模式按工作区组织，突出 Git、分支等工程信息；通用模式按文件夹组织，也可不关联文件夹。不是“通用不能写代码”或“编程不能办公”，主要是组织与入口不同。
新任务 New Task创建新的任务上下文。先选择执行者、设备/工作区，再给需求；快捷键请在设置中核对。新任务并不会自动继承你希望它知道的全部历史，应明确引用必要材料。
任务列表 / 工作区切换进行中或历史任务；使用分组、排序和置顶管理。多个任务可能共享同一文件目录，独立聊天并不意味着文件隔离。
需要我 My Attention集中处理待授权、待回答、待确认等事项。这里的搜索面向已加载事项，不等于全历史消息全文搜索。
右侧工作面 / 添加标签页打开文件、内置浏览器、终端或审阅，与对话并排。关掉视图不一定结束任务或后台进程。
任务监控看目标、计划、子任务、进程、工具、产物等，可固定或浮动。是执行观察窗，不是用一个总开关启停所有任务。
更多 More找到知识库、Repo Wiki 及未固定的功能，具体内容受设置与插件影响。没固定在侧栏不等于没安装。
左下账户菜单已观察到 Settings、Show pet、Appearance、Changelog、Get the mobile app、About Qoder、Sign out。About Qoder 的呈现方式以当前版本为准；Sign out 会影响账号会话，不用来练习。

设置 → 模式配置可以为不同模式配置主题和工程信息、监控等展示。侧栏菜单也可整理顺序、分组；固定项可能不允许移动。

4.2 新建任务时最重要的五个选择
  1. 执行者：顶部 Qoder 名称或箭头选择默认 Qoder、自定义 Agent 或团队。选择角色不等于自动安装它的全部依赖。
  2. 执行位置：本机、连接设备、SSH 等决定文件和工具在哪运行；远端路径不能当成本地路径。
  3. 工作目录：有文件产出时给出明确目录。首次信任工作区要检查目录范围，不要无意义地授予整个主目录。
  4. 模型与权限：选适合任务的模型；权限决定何时审批，不能靠换模型绕过权限。
  5. 输入与材料：说明结果、材料、格式、边界和验收。必要时添加模板、附件、Skill 或计划模式。

系统“打开方式 → Qoder”可把文件准备为新任务草稿，不自动执行，也不会理所当然替换已有草稿。PPT/Sites 模板作为附件就绪后，可按支持的模板流程发送；只有能力标签不等于有足够任务内容。

05 · 输入框：真正的“控制台”

5.1 输入、附件、@ 与 / 分别解决什么问题
按钮 / 操作怎么用判断是否成功
输入框写清目标、材料、交付物、约束和验收；不是越长越好，关键是没有歧义。Agent 能复述要产出什么、不能做什么。
添加上下文附加计划、目标等上下文入口，或引用相关材料。草稿中出现正确的上下文/模式，发送前再核对。
添加附件选择任务需要的文件或图片，等待附件就绪。文件名、数量、状态正确；失败附件可在支持的入口重试。
@ 引用引用文件、文件夹、任务、Agent、受支持的浏览器标签等。候选项受工作区和权限限制，文件候选遵循 .gitignore。草稿内引用的是正确对象；不是只打了一个类似文件名的普通字符串。
/ 能力选择查找 Skills、Plugins、Connectors、Commands、Agents；左右键可切分类。选择正确类型与来源，确认依赖和授权是否就绪。
上下选择 / Enter / Tab / Esc↑↓选择候选，Enter/Tab 加入，Esc 关闭选择面板。注意 Enter 在候选面板与普通输入框里作用不同。
建议问题空输入框中的建议可用 Tab 或右方向键填入草稿，再编辑。填入草稿不等于已经发送。
模型 / 访问权限在发送前选择后续使用的模型与审批方式。确认影响范围是当前任务/后续消息，不要以为改了全局所有任务。
发送 / 停止发送提交需求；停止结束当前执行，运行中按钮状态可能变化。停止不回滚已保存文件、已发消息或已提交的外部操作。

发送快捷键可在设置中选择；如果配置为 Enter，需留意候选面板与换行场景。若容易误发，请选择适合自己的发送方式。

5.2 执行中补充要求：排队、插话、撤回、移除

排队（Queue）与插话（Steer）是两种不同方式。新消息等待当前执行结束，适合下一阶段要求。插话（Steer）则尽早把修正送入正在执行的任务，但通常在安全处理点生效，不保证瞬时打断每个工具。

队列操作作用适用例子
插话 / 立即介入将补充约束交给活动执行轮次。“不要覆盖原文件，请另存。”越早发现越应明确说出。
撤回到输入框把未处理的排队消息拿回编辑。发现附件或要求写错。
移除删除尚未执行的排队项。下一步已经不需要了。
调整顺序改变排队消息处理次序。先检查结果，再继续格式化。

不要把“插话已发送”当作“工具已取消”。对于可能造成外部影响的错误，停止后仍要检查实际状态，不能直接重复操作。

5.3 问答面板、权限面板和计划审批不是同一个东西

问答面板用于补齐你拥有的决策：可逐题填写、保留草稿，再整体提交；“跳过全部”会留下空答案，不代表选择了推荐项。若开启静默跳过，等待时间、空答案处理与互动取消计时规则应以当前版本说明为准；重要决定不宜默认跳过。

权限面板让你决定某个动作能否执行；计划审批让你确认整体实现方向。批准一个计划，不应被理解成可以任意发送信息、扩大目录访问或删除无关文件。先看动作、目标对象、数据去向与是否可逆，再授权。

07 · 计划、目标和任务监控

7.1 Plan：先审方法，再批准执行

按钮含义操作建议
关闭计划模式不再强制先输出计划。关闭不代表已批准之前计划。
按计划执行批准按已审查方向推进。先看是否包含删除、上传、发布或付费。

7.2 Goal：围绕验收标准持续推进，不是无限许愿

从“添加上下文 → 目标”或 /goal 设置。一个好目标包含交付物、约束、完成证据：例如“生成能打开的预算表，公式正确，手算核对三项，原表不覆盖”。

目标面板可以编辑目标、暂停、删除目标，并展示耗时。可在设置中选择新目标的默认最大轮数，具体档位以当前版本为准。默认设置只影响新目标，不改已有目标。“不限”也可能因阻塞、用量限制或手动暂停而停止。

轮数不是时间、Token 或费用预算；到上限不代表完成。暂停目标不回滚已执行操作；删除目标也不等于删除已生成文件。

08 · 模型、费用与上下文

8.1 选模型不是找一个“永远最好”的名称

点击输入框的模型名打开选择器；相应快捷键请在设置中核对。官方按 Auto、Ultimate、Fast、Efficient 等定位解释自动平衡、复杂任务、速度和成本，但读者账号当前可选模型、倍率、繁忙状态、Free 标记与价格，以选择器实时显示为准；公开教程不能代替当前账户的用量和账单。

切换通常影响后续消息，保留已有上下文，不把历史重新计算一遍。模型管理的默认列表可配置显示项、上下文窗口和受支持的思考参数；点保存与取消的结果不同。

学习时先用当前默认模型；如果任务简单却调用很多工具，先缩小范围、提高要求清晰度，再考虑换便宜模型。复杂任务也要靠拆解和验收，不只靠“最强模型”。

8.2 自定义模型 BYOK 的字段与保存流程

设置 → 模型 → 添加模型。选择供应商，或 OpenAI Compatible / Anthropic Compatible；OpenAI 类还可能区分 Chat Completions 与 Responses 接口。

字段 / 按钮用途检查点

添加 Model ID / 多模型在同一配置下加入多个模型。每个 ID 必须被服务支持，显示名称不等于模型 ID。
窗口 / 视觉 / 思考 / 最大输出声明和调整模型能力及限制。不能把不支持的能力勾成支持；视觉理解不等于图像生成。

BYOK 一般由供应商计费，不等于所有 Qoder 服务免费；Repo Wiki 等仍可能使用 Qoder Credits。云端模型与本地模型目录也不应假定自动同步。生图、视频能力的套餐与 BYOK 限制按当前文档和界面核对；试验前先了解可能消耗的额度。

8.3 上下文百分比与 /compact：理解“记得住多少”

输入区域的上下文占用通常分系统内容、工具、Skills、消息等估算。它是当前模型可处理内容的占用，不是账单，不是磁盘空间；其中 Skill 数量也不是实际调用次数。

/compact 或“压缩上下文”将长历史提炼为较短摘要；运行中、内容过短或正在压缩时可能不可用。历史记录还在，但模型接下来依赖的摘要可能丢失细节。金额、文件名、禁止事项、精确验收标准等关键内容应在后续明确重申。

9.2 外部 Chrome/Edge 与桌面控制分别何时用

外部浏览器连接：适合你已经在 Chrome/Edge 登录的工作系统。Qoder 开关、浏览器扩展、连接状态、网站登录与操作授权是不同层次。配置后应使用新的公开页面做只读验证，并关闭临时验证标签。连接成功不代表网站登录和业务操作也已验收。

桌面控制：通过截图和鼠标键盘操作配置好的桌面，适合没有 API 的原生界面。支持的平台、桌面会话与环境依赖以当前产品和官方指引为准；不能把某个 X11 环境的可用性推广为所有 Linux/Wayland 都支持。

需要放开鼠标吗？只有 Agent 正在接管同一桌面的鼠标键盘时，才需要你暂停输入和切换窗口；不要让多个 Agent 同时操控这个桌面。普通文件处理、接口调用或后台浏览器读取通常不需要你停用鼠标。开始接管、需要你登录或授权、结束接管时应明确交接；前台意外切换时先停止输入，不把原因直接归咎于用户。

AppShot：捕捉前台应用截图与可访问性文字加入草稿，不自动操作或发送。官方明确的平台包括 macOS 14+、Windows 10+；Linux 的可用性应另行核实。全局组合键是左右修饰键组合，不能误写成双击同一个键。

录制回放：文档明确 macOS 14+；灵动岛、锁屏控制、iPhone 等能力也有平台条件。不能将它们当作 Linux 必备项强行配置。

登录、验证码、CAPTCHA、支付资料应由你在真实服务页面完成。不要把敏感字段发给 Agent，也不要要求通过截图、剪贴板或其他通道绕过凭据保护。

11.3 PDF 操作工具集：能做什么，不能保证什么
工具用途适合的要求
pdfinfo / pdffonts查看页数、元数据、字体。“先检查这份文件是否有文本层、多少页。”
pdftotext提取已有文字层。“提取文本，抽查页码和段落；为空要说明。”
pdfimages / pdfdetach提取图片或附件。“提取内嵌图片，不修改源 PDF。”
pdfseparate / pdfunite拆页、按指定顺序合并。“第 1–3 页单独另存，再与第二份合并。”
pdftoppm / pdftocairo将页面转换为 PNG 等格式。“导出可读预览并检查清晰度。”
pdftohtml转换为 HTML。“转换后检查阅读顺序；不要求完美还原所有排版。”
pdfsig / pdfattach检查数字签名信息 / 添加附件。签名可信度还依赖证书与验证环境；改文件可能破坏原签名。
Poppler 文本提取不等于 OCR。扫描图片 PDF、复杂多栏、公式和表格都可能需要额外识别与人工校对。安装成功不等于所有 PDF 已实测。加密文件必须有合法访问权限，不尝试绕过限制。

13 · 扩展市场、Skills、MCP、命令与 Hooks

13.1 扩展的正确状态链：安装只是第一步
找到正确来源→安装 / 启用→加载 / 连接→必要认证→最小任务验收

第三方发布者、市场渠道、插件包和服务提供商可能不是同一家。“Qoder 公开市场”不代表每个条目都是 Qoder 官方开发。先查同类能力是否已有，再看来源、版本、依赖、数据去向和权限。

13.3 Plugins 与连接器：包、工具、界面分别看
按钮 / 入口用途注意
扩展 → Plugins → Install / Installed安装和管理成套扩展。父插件启停可能影响内部 Skill、MCP 等组件。

自定义 MCP 字段速查

Name 用于识别条目；transport 指传输方式；通常在 command（本地进程）与 url（远程服务）中按类型选其一；args 是字符串数组；env 是字符串值对象；显式 cwd 要用绝对路径。timeout 单位是毫秒，当前文档范围为 1000–2147483647，留空采用默认。

配置文件名是 settings.json，其中的 MCP 对象叫 mcpServers，不是 setting.json。这不意味着 App 所有普通设置都能在该文件里修改。超时不证明服务没有执行写入，不能靠无限加大超时解决所有问题。

云同步并不支持任意本地连接器。符合条件的独立用户级 HTTPS 连接与 stdio、插件内置、AppHub、带静态 headers 或 URL 查询参数的连接有不同限制；同步前审查数据和凭据范围。

13.4 Hooks：自动触发器，不是普通“增强开关”

设置 → Hooks 可看事件、来源、处理命令、matcher、timeout 和配置源。处理类型可包含 command、http、prompt、agent，事件涉及工具前后/失败、会话、权限或压缩等生命周期。

Hook 可能在你没再次发消息时产生真实副作用。看到条目不代表 Runtime 已加载、事件已匹配或执行成功；应在低风险测试中检查结果和相关日志。避免添加职责不清的“通用万能 Hook”，防止无意上传数据、修改文件或重复执行。

14 · 自定义 Agent、临时子 Agent 与持久团队

14.1 自定义 Agent：先定义职责，再选择工具

设置 → Agent → Create Agent，选择空白或模板。填写 Name、Description、Instruction content、Model、Default permission，并选择 Skills、MCP、Plugins；工具权限页可编辑允许、拒绝和默认审批规则。

按钮 / 字段作用建议
Name / Description让你和负责人知道它负责什么。用“资料核验助理”比“最强全能王”更容易正确分派。
Instruction content定义输入、流程、输出、边界和停止条件。写具体验收，不用“永不失败”“永不提问”这类不可实现约束。
Model / Default permission规定默认推理能力与审批行为。默认权限不应无条件最大化。
Skills / MCP / Plugins限定该角色实际可加载的能力。模板依赖可能未安装；插件未选中不一定自动加载。
Save Agent保存角色配置，之后可在新任务执行者中选择。对话生成的草稿不等于已保存的 Agent。
Continue configuration从对话中的草稿进入配置表单。必须由你审阅并在表单保存，草稿工具成功不是创建成功。
Local / Cloud决定角色创建类型与执行环境。创建后不可随意切换类型；本机密钥不自动同步。
启用 / 停用 / 归档控制角色是否可用与如何展示。停用可能影响正在运行的任务，历史保留与继续运行不同。

无需为了使用 Agent 而先创建自定义角色；有稳定分工需求时再添加。默认 Qoder 足以承担多数通用工作；只有重复工作需要固定边界时才值得创建专用角色。

14.2 团队不是“开得越多越好”：先区分两种多 Agent

任务内临时子 Agent：总控在某个任务中分派有边界的研究、实施或验证工作，结束后汇总；适合拆分独立子任务。持久 Agent Team：在设置里保存负责人和固定成员，今后重复选用。

设置 → Agent Team → Create Agent Team → Blank setup 或 Template → Use this template，选择 Team Leader 和 Additional members，再 Save Agent Team。已阅读的 Desktop 官方团队页面描述为1 个负责人、1–4 个额外成员，不能据此承诺当前 UI 支持“1+10”持久成员。临时并行子任务与这个成员数限制不是同一机制。

操作效果检查点
选择负责人 / 添加或移除成员决定任务协调与执行分工。避免多个成员同时写同一文件；每人有独立产出与验收。
保存团队 / 启用协作建立可复用团队，可能需要成员注册或启用协作能力。弹出授权时审查范围，不能由团队提示词替代。
新任务执行者 → Agent Teams将任务交给团队负责人。负责人接到任务不等于成员全部结束。
本机 / 云端 / 同账号设备成员在支持的环境组合角色。取决于在线状态、执行位置和权限；SSH 等入口存在限制。
停用团队停止团队作为可选执行者的使用。不应假定所有成员的独立任务也自动停止。
如果需要更大规模的负责人和执行角色分工，先确认当前产品限制、执行方式与预算，再设计批次、临时子任务或其他受支持方案。对团队结构的偏好不等于已经授权创建团队。

来源：自定义 AgentAgent Teams

16.2 Discussion：人和 Agent 在同一条讨论里协作

18.1 Local 与 Worktree：隔离改动不等于隔离权限

21.2 安全扫描、Better Harness 与代码索引

22 · 快捷键：按场景核对，不必死记

不同平台、版本和个人设置可能采用不同绑定。本公开版不发布个人设备的键位记录，也不把某个平台的默认值当成所有读者的实际配置。请打开“设置 → 快捷键”，按动作名称查询并记录自己的组合键。

22.1 先学会查找常用动作
动作组建议核对的动作练习时的检查点
任务与窗口新任务、新窗口、切换任务、全局搜索、当前任务查找。新任务不是新窗口；全局搜索不是当前任务内查找。
输入与模型发送消息、切换模型、切换计划模式。候选面板、输入框和其他窗口的焦点可能改变按键语义。

每次只练三到五个动作。先通过菜单找到功能，再测试对应快捷键；不确定时优先使用明确的菜单入口。

22.2 语音快捷键与冲突排查

分别查询“语音输入启停”“实时语音”“实时麦克风”“实时播报静音”。采集与播放是不同方向，静音播报不等于停止麦克风。

如果同一个组合键绑定多个动作，先检查触发场景、焦点、操作系统热键和其他应用的占用。需要修改时只调整明确冲突的绑定，记录原值，并在适合的环境中验证。

录音相关按键不适合随手测试：先确认周围环境、麦克风权限和必要的参与者同意。macOS 与 Windows/Linux 的修饰键也不能未经核对就机械替换。

23.2 资料研究：要来源，不要“像真的”
围绕[问题]做一份供[受众]使用的研究简报。

先区分已知事实、待核查点和我的假设；对关键结论给可打开的来源链接。

仅使用公开资料，不登录账号，不上传我的本地文件，不发布到外网。
验收：抽查至少三条关键结论与原文一致，所有内部目录可用。
23.3 Excel 分析：先保护原表，再计算
请分析[Excel/CSV 文件]中的[工作表或范围]。
先检查字段、行数、空值、重复值、日期和金额格式，再计算[指标]。
不要覆盖原文件；新建一个 XLSX，保留原始数据页，另建汇总与说明页。
需要可更新的计算时使用公式，并说明统计口径。

23.4 Word / PPT：从受众和结论出发

所有数字沿用资料并标明出处，不编造案例和引用。
验收：逐页检查文字截断、重叠、字体和阅读顺序；抽查可编辑性。

23.5 PDF：指定页码与成功标准
处理我提供的[PDF 文件]：把[页码范围]另存为一份，再按[指定顺序]合并。
先检查页数、是否加密、是否有文本层；不修改源文件。
如果涉及文字提取，区分原生文字与扫描图片，提取失败明确报告，不把空文本当成功。
验收：输出页数、顺序与要求一致，抽查首尾页可正常渲染。
如需额外 OCR、安装依赖或解密授权，先说明再继续。
23.6 编程 / 网站：预览与发布分开
在[现有项目或新目录]实现[功能]，面向[用户]。
先理解现有结构和约定，范围只限[要改部分]，不做无关重构。
交付可运行结果，补充与修改相关的测试，并实际运行可用检查。
接口不明确时先做只读验证；演示数据必须明确标注，不能伪装成真实服务结果。
网站先只做本地预览，不发布、不购买服务、不填写密钥。

23.7 多 Agent：总控负责验收，不只负责转发
你担任总控，将[任务]分成真正能独立推进的子任务。
先说明哪些步骤能并行、哪些依赖前序结果；按需要使用少量临时子 Agent。
每个子任务写清输入、目标、允许修改的文件范围、输出和验收标准。
不要让多个执行者同时改同一文件；研究、实施、复核尽量分开。
子 Agent 的“已完成”只是一条报告，总控必须检查实际文件、计算或测试证据。
失败时先诊断，不重复制造副作用；没有权限不改用绕过路径。
不创建持久团队、不增加云资源、不扩大权限，除非我另行明确同意。
